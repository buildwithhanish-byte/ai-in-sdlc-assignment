Did the prompt change help?

Under the provisional key, each baseline run caught 8 of 9 defects (88.9%), missed 1 of 9 (11.1%), and raised no false alarms on 3 clean cases. Across three baseline runs that is 24/27 caught, 3/27 missed and 0/9 false alarms. Those are repeated reviews of the same cases, not new independent samples.

The changed prompt caught 6 of 9 defects (66.7%), missed 3 of 9 (33.3%), and again raised no false alarms on 3 clean cases. Its caught rate was 22.2 percentage points lower than the baseline rate. Cases 05 and 07 changed from caught to missed; case 09 was missed in every run. All other case verdicts stayed the same.

I would not claim an improvement from this prompt change. It made the reviewer more conservative about omitted authorization and logging context, without reducing the observed false alarm count because the baseline already had none. Under this key it lost recall. The cautious responses themselves are defensible given the restricted inputs, which limits the strength of that conclusion.

Excluding the four context-sensitive cases, every pass caught all five remaining defects and correctly left all three clean cases unflagged. The comparison therefore gives no evidence of a difference on that smaller subset. It does not establish that the prompts are equivalent or reliably safe.

Confidence in generalisation is low. One clean-case error would change a per-run false alarm rate by 33.3 percentage points. There are only three clean examples, the added pair shares one origin, labels were AI-assisted, and the changed prompt was run only once. A sensible next experiment is a larger independently labelled holdout set with realistic context, tested separately rather than changing this completed experiment.

Limits and scoring choices

Caught and missed rates use defective cases as their denominator. False alarm rates use clean cases. A finding must explain the real failure; vague advice does not count. Style suggestions are not false alarms. Additional unsupported findings are described in individual scoring notes. Confidence values are the reviewer’s own words, not calibrated probabilities.

There are only 12 unique cases and three clean examples. The repeated baseline outputs are correlated, so pooled 27 defective reviews and nine clean reviews are not 36 independent examples. Four supplied cases were shown during the workshop, which further limits generalisation. The changed prompt ran once, and fixed run order leaves possible time effects. These results support a small descriptive comparison, not a claim of statistically established improvement.

The two added cases come from one repository defect reproduced during this assignment with AI assistance. They are a related buggy/fixed pair, not two past employment incidents. The corrected case is clean within its explicit shared-object in-process contract, not proof of production or distributed safety. It also supplies more context than some original diffs.
